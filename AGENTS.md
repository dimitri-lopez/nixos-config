## Window Managers

### Available Window Managers
The following window managers are configured and selectable:

| WM | Type | System Config | Home Config | Notes |
|----|------|--------------|-------------|-------|
| `xfce` | X11 DE | `modules/xfce/xfce.nix` | `modules/xfce/xfce-home.nix` | Full desktop environment with panel, whisker menu, Thunar |
| `driftwm` | Wayland infinite canvas | `modules/driftwm/system.nix` | `modules/driftwm/home.nix` | Trackpad-first infinite canvas via `malbiruk/driftwm` + Noctalia shell |

### Currently Selected Window Manager
The active window manager is set in **`readme.org`** under the section `* User Settings`.

Look for:
```nix
userSettings = {
  # Options: "xfce", "driftwm"
  wm = "driftwm";
};
```

This value is consumed by `flake.nix` in the `selectedDesktop` attribute set, which conditionally loads the correct system and home modules:

```nix
selectedDesktop = {
  xfce = { system = [ ./modules/xfce/xfce.nix ]; home = [ ./modules/xfce/xfce-home.nix ]; };
  driftwm = { system = [ ./modules/driftwm/system.nix ]; home = [ ./modules/driftwm/home.nix ]; };
}.${userSettings.wm};
```

**To switch WMs**: edit `readme.org`, change `wm = "...";`, then run `./sync.sh`.


## Workflow

```bash
# Single entrypoint: tangle, sync noctalia, rebuild
cd ~/.dotfiles && ./sync.sh

# Or manually:
# 1. Tangle (with fallback: doom -> emacs batch -> python)
python3 tangle.py readme.org

# 2. Rebuild
home-manager switch --flake .
sudo nixos-rebuild switch --flake .
```

## Common Commands

```bash
# Single entrypoint for all changes
./sync.sh

# Home only
home-manager switch --flake .

# Home + System
home-manager switch --flake . && sudo nixos-rebuild switch --flake .

# With updates
home-manager switch --flake . --update && sudo nixos-rebuild switch --flake . --update

# Update packages
sudo nixos-rebuild switch --flake . --upgrade
```

## Literate Programming

- **Source of truth is `.org` files.** All `.nix` files (except `hardware-configuration.nix`) are generated and should be treated as read-only.
- Edit `.org` files, not `.nix` files directly. Upon tangling they will be regenerated.
- `readme.org` is the master file. It `#+INCLUDE`s all other `.org` files.
- Tangle with: `doom +org tangle readme.org`, or `python3 tangle.py readme.org`

## Inbox Workflow

- New packages or settings go to the **Inbox** section at the top of `readme.org` first
- After verifying they work, move to the appropriate `.org` module file

## Agent Rules (CRITICAL)

1. **`.org` files are the ONLY editable source.** All `.nix` files (except `hardware-configuration.nix`) are GENERATED and READ-ONLY.
2. **Never edit `.nix` directly.** If an agent edits a `.nix` file, the change will be lost on next tangle.
3. **Consult `manifest.json`** to find which `.org` file generates which `.nix` file.
4. **Adding a package?** Edit the appropriate `.org` file's code block, then run `python3 tangle.py readme.org` before rebuilding.
5. **Adding a new module?** Create a new `.org` file, add its `#+INCLUDE` to `readme.org`, and update `manifest.json` by running `python3 manifest.py`.
6. **`sync.sh` is the single entrypoint** for applying changes. It unlocks `.nix` files, tangles, regenerates manifest, syncs noctalia, rebuilds, then re-locks `.nix` files.

## Important Notes

- Edit `.org` files, not any of the `.nix` files directly. Upon tangling they will be repopulated.
- `.nix` files are set to read-only (`chmod 444`) after tangling. `sync.sh` unlocks them before tangle and re-locks them after.
- `configuration.nix` requires sudo for ownership: `sudo chown root configuration.nix`
- Window manager is configured via `userSettings.wm` in readme.org's User Settings section
- When creating new files (especially *.nix), add them to the appropriate `.org` file using `#+begin_src nix :tangle ./path/to/module.nix` blocks

## Module Locations
- System modules: `~/.dotfiles/system/*.nix`
- Home modules referenced in `home.nix` imports
- Reusable components: `~/.dotfiles/modules/<component>/default.nix` or `~/.dotfiles/modules/<component>.nix`

## System vs Home-Manager Split

Window manager and other compositor-specific configs should be split:
- **System config** (`system/*.nix`): Login managers, compositor services, seat management
- **Home config** (`modules/*-home.nix`): User packages, dotfiles, activation scripts

This allows cleaner WM switching - changing `userSettings.wm` loads the right modules automatically.
