**Investigation findings:**

The "Unable to start session" error occurs because srwc is a Wayland compositor but the system is configured with LightDM (an X11 display manager) and no wayland session file exists.

Root causes:
1. No wayland session `.desktop` file exists for srwc in `/share/wayland-sessions/`
2. srwc needs to be launched via its CLI (`srwc start`), not as a standard session
3. The current configuration has `services.xserver.enable = true` but doesn't create a wayland session entry

**Fix to add to readme.org (srwc window manager section):**

Use UWSM (Universal Wayland Session Manager) to wrap srwc. This handles systemd session integration and creates the proper desktop entry.

```nix
  programs.uwsm = {
    enable = true;
    waylandCompositors = {
      srwc = {
        prettyName = "srwc";
        comment = "srwc Wayland compositor managed by UWSM";
        binPath = "${inputs.srwc.packages.${pkgs.stdenv.system}.default}/bin/srwc";
      };
    };
  };

  services.displayManager.defaultSession = "srwc-uwsm";
```

This ensures the session is started properly under systemd and is selectable in LightDM as "srwc (UWSM)".
